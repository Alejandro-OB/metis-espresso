# Compatibilidad de EKO 3.1.0 a 3.2.0

EKO 3.2.0 permite publicar una extracción que el dispositivo no vio terminar
porque se cortó la energía. Hasta 3.1.0 las formas exigían inicio y fin en toda
extracción, y una preparación cortada solo podía quedarse fuera del almacén o
entrar con instantes inventados. Ninguna de las dos cosas es aceptable: la
primera borra un hecho del registro y la segunda afirma lo que no consta.

Cambios:

- se añade el individuo `edt:UnexpectedPowerLoss` como `edt:TerminationCause`;
- `edt:ExtractionShape` deja de exigir `edt:startTime` y `edt:endTime`
  (conserva el máximo de uno de cada uno);
- `edt:ExtractionStartShape` y `edt:ExtractionEndShape` los exigen salvo cuando
  la extracción declara `edt:hasTerminationCause edt:UnexpectedPowerLoss`;
- el módulo de simulación pasa a 1.1.1 solo para importar EKO 3.2.0.

No se añade una clase `IncompleteExtraction`. La causa de finalización ya
distingue la extracción cortada, y una clase nueva duplicaría esa información
con el riesgo de que las dos se contradigan.

## Procedimiento

1. Conservar copia y versión del grafo 3.1.0.
2. Cargar `ontology/espresso-dt.ttl` y `ontology/espresso-dt-shapes.ttl` 3.2.0.
3. Ejecutar las formas SHACL y `python tests/validate.py`.

Todo grafo válido en 3.1.0 sigue siéndolo en 3.2.0: las formas solo se relajan
para el caso nuevo. Por eso no hay SPARQL Update para los datos existentes.

No se debe completar el inicio o el fin de una extracción cortada con el
instante del rearranque ni con una duración estimada. Si el dispositivo no
tenía hora de pared al empezar, el inicio tampoco consta y se omite.
